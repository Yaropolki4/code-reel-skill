# Рилс о коде в Remotion

На входе — текст озвучки (иногда сразу аудиофайл и/или готовый покадровый таймлайн). На выходе — проект Remotion с роликом 1080×1920, 30 fps, который зациклен, читается на телефоне и звучит как серьёзный технический канал.

Скилл несёт готовую базу: камера, карточки кода, терминал, заголовок хука, субтитры, движок звука с библиотекой Mixkit, распознавание озвучки. Не пиши это заново — копируй шаблон и пиши только сцены ролика.

## Что где лежит

Все пути — от папки этого скилла.

- `scripts/init_project.sh` — готовит проект: создаёт blank-проект Remotion (или берёт существующий), копирует шаблон, ставит пакеты, скачивает звуки.
- `assets/template/` — то, что копируется в проект: `src/reel/` (компоненты, анимация, тема, субтитры, звук), `scripts/` (сведение звука, распознавание, субтитры). Образец блока — `src/reel/BlockExample.tsx`.
- `references/design.md` — палитра, шрифты, раскладка и безопасные зоны, правила движения, каталог компонентов. **Прочитай перед тем, как писать сцены.**
- `references/sound.md` — какой звук на какое действие, уровни, как писать `sfx_cues.py`. Прочитай перед звуком.
- `references/voice-and-captions.md` — распознавание озвучки, синхронизация, субтитры. Прочитай, когда есть аудио.

## Порядок работы

### 1. Таймлайн

Если пользователь прислал готовый таймлайн — работай по нему. Если только текст — сначала напиши покадровый таймлайн по правилам из `references/design.md` (раздел «Таймлайн»).

Перед сборкой проверь таймлайн и скажи пользователю о проблемах — это экономит переделки:
- **техническая точность**: команды и их вывод такие, как в реальных инструментах (например, `git diff` не печатает «0 files changed», `git commit` без `-m` открывает редактор). Всё, чего в реальном инструменте нет, — пометь как иллюстрацию;
- **вёрстка**: «слева–справа» обычно не влезает в 1080 px с отступами — ставь блоки друг под другом;
- **плотность**: не больше одного нового элемента за раз (подробнее — в design.md).

**Залипательная анимация хука — обсуди до того, как писать код.** Первые ~2 с ролика (пока звучит первая фраза и въезжает заголовок) — гипнотическая анимация по теме ролика, от которой трудно оторваться. Это отдельный вопрос к пользователю вместе с таймлайном: предложи 3–4 концепции (каждая — одной-двумя фразами: что движется и как это связано с темой), отметь рекомендуемую и дождись выбора. Не собирай хук «по умолчанию» и не ставь простое появление элементов. Требования — design.md, «Залипательный хук».

Покажи найденное и предложенные правки коротко, затем собирай. Правки по точности вноси сразу, если пользователь не против.

### 2. Проект

```bash
bash <папка скилла>/scripts/init_project.sh <папка проекта> [--force]
```

Скрипт не перезаписывает существующий `src/reel` без `--force`, а `Root.tsx` и `remotion.config.ts` сохраняет в `.bak`. Если в проекте уже лежит прошлый ролик — спроси, стирать ли его, прежде чем запускать с `--force`.

### 3. Озвучка (если уже есть)

Если аудио есть до сборки — сначала распознай его (`references/voice-and-captions.md`) и размечай удары сразу по секундам слов. Это точнее, чем растягивать потом. Если озвучки нет — размечай по темпу ~2,7 слова/с, а потом синхронизируй картой времени.

### 4. Сцены

Раздели ролик на **блоки** — отрезки между склейками. Каждый блок — свой файл `src/reel/Block<Имя>.tsx` с `const START = <секунда начала>` и `const t = useBlockTime(START)`; все удары внутри — в тех же глобальных секундах. Шаблон блока — `src/reel/BlockExample.tsx`. Строки кода — в `src/reel/lines.ts`. Нужен элемент, которого нет в `ui.tsx` (чип, бейдж, пайплайн CI, уведомление, дерево файлов), — допиши его в том же стиле (design.md, «Каталог компонентов»).

Собери блоки в `src/reel/Reel.tsx` (`Series`, длительность `blockFrom(конец) - blockFrom(начало)`) и выставь `durationInFrames` в `src/Root.tsx`. Удали `BlockExample` из `Reel.tsx`.

Петля: последний кадр ролика должен в точности совпадать с первым — та же раскладка, камера `(540, 795, s=1)`, тон фона. Первый кадр — не код: что-то понятное за полсекунды без знания синтаксиса (уведомление, результат, файл).

### 5. Проверка картинки

`npm run lint` (eslint + tsc), затем рендер черновика и кадров:

```bash
npx remotion render <id> /tmp/draft.mp4 --scale=0.5
npx remotion ffmpeg -ss <сек> -i /tmp/draft.mp4 -frames:v 1 /tmp/f.png   # смотри кадры через Read
```

Смотри минимум по кадру на сцену плюс первый и последний (петля). Типичные огрехи: текст или край карточки обрезан, элементы налезают друг на друга, лигатуры (`>=` → `≥`; в `Code` они уже выключены), «прыжок» множителя у смэш-ката на кадре до склейки.

### 6. Звук

Опиши события в `scripts/sfx_cues.py` по правилам из `references/sound.md`, затем:

```bash
python3 scripts/mix_sfx.py   # → public/sfx.wav
```

Включи `HAS_SFX = true` в `src/reel/Sfx.tsx`. Ты не слышишь звук — проверяй уровни скриптом и прямо говори пользователю, что на слух проверить должен он.

### 7. Озвучка и субтитры

По `references/voice-and-captions.md`: `public/voice.wav` → `node scripts/transcribe.mts` → карта времени (если ролик собирали до озвучки) → `python3 scripts/captions_from_whisper.py` → `HAS_VOICE = true` → пересвести звук (сайдчейн под голос).

### 8. Превью и экспорт

Превью: `npx remotion studio` (композиция по id). Рендер — только когда пользователь просит:

```bash
npx remotion render <id> out/<имя>.mp4 --codec=h264 --crf=16
```

Трендовую музыку пользователь добавляет в самой соцсети — вшитая лицензируемая музыка может быть заглушена.

## Стиль по умолчанию

Соблюдай, пока пользователь не попросит иначе:

- **Отступы**: соцсети срезают 20–30 px по бокам — карточки на x = 110…970, край контента не ближе ~60 px к краю экрана.
- **Спокойный темп**: элементы появляются по одному с паузой ≥ 0,3–0,5 с, чтобы глаз успевал зацепиться; входы плавные (пружина почти без перелёта), без лишних вспышек. Убирай элементы, которые дублируют смысл.
- **Неподвижная камера**: в блоке камера стоит (`s = 1`, постоянный `fy`), без микрозумов, наездов и дрейфа. Один короткий пан — только если иначе новый контент не влезет. Динамику дают элементы: каскад строк, бегущая подсветка, счётчики, смена состояний. Подробнее — design.md, «Камера».
- **Лёгкая тряска**: толчки камеры маленькие (значения уже заданы в `shake()`).
- **Серьёзные и тихие звуки**: без мемных звуков и «игровых» паков; «аппрув» `ding-small` — 0.1–0.2.
- **Озвучку не прерывать**: не вставляй паузы в запись, чтобы удлинить сцену. Нужно больше времени — пусть анимация продолжается под следующей фразой, а склейка уходит на ударное слово позже.
- **Заголовок хука появляется сразу**: 2–3 крупных слова въезжают на 0,1 и 0,3 с, каждое за 0,12 с (`ramp`, outExpo), не дожидаясь слов в озвучке. Первый кадр — без заголовка (петля). Под оба слова — один тихий `swoosh-mid` ~0.25.
- Ничего не делай с ресурсами пользователя «тихо»: перед удалением старого ролика или перезаписью спроси.

## Общение

Пользователь смотрит результат в Studio и даёт короткие правки («тряски меньше», «звуки не те», «отмена»). Отвечай по делу: что изменил, где это в коде, что проверить глазами и ушами. Если правка неоднозначна («сверканий меньше» — каких?) — уточни, прежде чем менять всё подряд.
