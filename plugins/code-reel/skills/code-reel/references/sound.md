# Звук рилса

Звук — чистый монтажный, как в хороших технических роликах: **никаких мемов** (vine boom, bruh, windows xp error, anime wow) и «игровых» паков.

## Как устроено

- `scripts/mix_sfx.py` — движок + библиотека `LIB` (роль → id Mixkit). Сводит всё в одну дорожку `public/sfx.wav`. Одна дорожка, а не десятки `<Audio>`: иначе Studio лагает.
- `scripts/sfx_cues.py` — события ЭТОГО ролика: `DURATION` и функция `build(cue, typing)`.
- `scripts/fetch_sfx.sh` — скачивает все id из `LIB` в `sfx-src/wav/mk<id>.wav`. Новый звук: найди на mixkit.co, id — в ссылке `assets.mixkit.co/active_storage/sfx/<id>/<id>-preview.mp3`; добавь роль в `LIB`, запусти fetch.
- Время событий — секунды таймлайна блоков (как в `Block*.tsx`); карта `timewarp.json` переводит их в секунды озвучки сама.

```python
cue(at, role, vol, anchor="onset", dur=None, offset=0.0, pitch=0, fade_in=0.0, fade_out=0.15, lead=None)
typing(t0, t1, chars, back=False, vol=0.32)   # клики печати / backspace на отрезке
```
- `anchor="peak"` — для свушей, хлыста, райзера: громкая точка звука встаёт ровно на склейку/слово. Остальное — `onset`.
- `lead` — сколько секунд звука оставить перед пиком при `anchor="peak"`; разгон обрезается с fade-in 0,05 с. У `whip` по умолчанию 0,3 (`DEFAULT_LEAD` в `mix_sfx.py`). Без обрезки звук с peak-якорем начинает звучать задолго до удара и ложится на предыдущую сцену. Слышимый разгон до пика: `whip` 0,7 с, `rewind-glitch` 0,8, `swoosh-long` 0,4, `impact` 0,3 (обычно с offset=0.5), `swoosh-mid` 0,16, `riser` 1,5 (так задуман).
- `offset`/`dur` — кусок сэмпла: `impact` с `offset=0.5` начинается сразу с удара; `glass` с `dur=0.1` — только щелчок трещины.
- `pitch` — лесенка: три галочки подряд `0, +3, +7`; три попа `0, +2, +4`; повторяющийся свуш — `-2`.

## Действие → звук

| Действие в кадре | Звук |
|---|---|
| Печать | `typing(...)` — живые нажатия из записи клавиатуры, не чаще 14/с |
| Стирание | `typing(..., back=True)`; код «выброшен» целиком → в конце `paper` |
| Enter, принять автодополнение | `enter` (+ `bass` 0.25–0.3, если вспышка) |
| Мелкий элемент появился (чип, бейдж, индекс) | `click`, серия — `click` с pitch лесенкой |
| Всплывающее окно (подсказка, панель) | `pop` |
| Крупный блок въехал (карточка, консоль) | `swoosh-mid` (peak на середину въезда) + `bass` 0.25 на приземлении |
| Рамка акцентная/оранжевая | `tick` |
| Красная рамка | `tick` + `bass` 0.3 |
| Зелёная рамка, галочка, «аппрув» | `ding-small` **0.1–0.2** (серия лесенкой — 0.1); главный позитив ролика — `ding-small` ~0.13, pitch=-2 + тихий `swoosh-short` 0.25 |
| Зачёркивание | `marker` |
| Ошибка в рантайме (консоль) | `impact` (offset=0.5) + `error` |
| Подчёркивание, «нет», мягкая ошибка | `error-soft` |
| Шаг CI упал | `fail` + `bass` |
| Бейдж-штамп (FAILED) | `stamp` (+ `bass`) |
| Пан камеры (редко) | без звука или `swoosh-long` 0.25 |
| Подсветка бежит по строкам, каскад строк | `swoosh-long` 0.25 (fade_in 0.1, dur ~1.2) / `swoosh-mid` 0.3 |
| Хлыст | `whip` peak на момент склейки (`lead` 0,3 — по умолчанию) |
| Смэш-кат | (`riser` peak ~0,15 с до склейки →) пауза → `impact` offset=0.5 |
| Перемотка | `rewind` (offset≈1.1, dur≈0.4); в петлю — `rewind-glitch` dur 0.4 |
| Глитч | `glitch` |
| Что-то скрыто/закрыто | `lock`; мерцание — `buzz` |
| Трещина / разлёт | `glass` dur=0.1 / `glass` целиком |
| Счётчик крутится | `counter` offset=0.1 dur=0.5–0.66, громкость 0.6–0.8 |
| Линия-связка | `zip` |
| Бегут строки | `data` offset=0.49 dur=0.35 |
| Пульсация | `pulse` dur=0.25, тихо |
| Заголовок хука (слова на 0,1 и 0,3 с) | один тихий `swoosh-mid` 0.25 peak на ~0.14 с на оба слова — два свуша через 0,2 с слипаются |
| Пуш-уведомление | `notify` + `ding-small` pitch=-5 тихо + `bass` |
| «Красная» сцена | подложка `hum` 0.2–0.26 с fade; через склейку петли — без провала (сегмент в начале на полной громкости и сегмент в конце до самого конца) |

## Правила микса

- Одновременно — не больше двух звуков; печать сама приглушается возле акцентов.
- Громкости `vol`: акценты (склейки, хлысты, impact) 0.6–0.75; свуши, клики, тики 0.25–0.5; «аппрув» `ding-small` 0.1–0.2. Сомневаешься — ставь тише: громкий звук замечают сразу, тихий — нет.
- Дорожка нормализуется по пику до −6 dBFS. Пик обычно даёт `impact` на смэш-кате; если убавляешь звук, который сам был пиком, остальные после нормализации станут громче — проверь замером.
- С озвучкой: сайдчейн (под голосом −45%) включается сам, если есть `public/voice.wav`; в `Sfx.tsx` громкость дорожки звуков 0.45 от голоса.
- Петля: звук с peak-якорем на первом кадре (свуш на 0.0) обрезается — продублируй его на последней секунде (`cue(DURATION, "swoosh-mid", …, anchor="peak")`), его разгон прозвучит в конце и подведёт к удару при зацикливании. Если первое слово начинается позже 0,1 с, дублировать не нужно.
- Убрал элемент из кадра — убери и его звук.

## Проверка

Ты не слышишь звук. После сведения:

- Замерь пики/RMS по ключевым отрезкам: тишина перед ударом смэша, совпадение уровня в начале и конце для петли.
- **На каждую жалобу «звук X громкий» сначала найди, что на самом деле звучит в этот момент.** Пройди по `cues` (как это делает `main()` в `mix_sfx.py`: start = at − ref, end = start + длина) и выведи все звуки, которые пересекают окно жалобы, с их пиком в этом окне. Часто громким оказывается разгон соседнего звука (например, хлыста следующей склейки), а не тот, на который жалуются.
- Скажи пользователю, какой звук на каком событии (роль, id Mixkit, громкость, строка в `sfx_cues.py`), и попроси оценить на слух. Если он говорит «звуки не те» — уточни, какие именно, и меняй роль в `LIB` или громкость события, а не всю схему.
