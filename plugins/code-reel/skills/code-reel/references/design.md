## 1. Холст и безопасные зоны

1080×1920, 30 fps. Зоны рассчитаны на Reels / Shorts / TikTok.
- Верх 0–230 px — интерфейс приложения, пусто.
- Низ 1360–1920 — интерфейс приложения и субтитры. Субтитры стоят на y ≈ 1400 (компонент `Captions`), ниже ничего.
- Контент — в полосе 230–1360, её центр — `CY = 795` (точка, куда камера ставит фокус).
- По бокам срезается 20–30 px: карточки x = 110…970 (ширина 860); узкие — x = 160…920. Правый край не занимай важным.

## 2. Палитра и цвета как смысл

`C` в `theme.ts`: `bg`, `card`, `stroke`, `popup`, `text`, `sec`, `muted`, `accent`, `green`, `orange`, `red`, `violet`, `deep`. Палитру меняют под свой канал в `theme.ts`, смысл цветов сохраняют:

- `accent` — главный акцент, выделение, промпт `$`, текущее слово субтитров;
- красный — ошибка, «плохой» вариант;
- зелёный — правильно, успех, строки в коде;
- оранжевый — типы, версии, ключевые значения;
- `violet` — ключи YAML/JSON, числа;
- серый — второстепенное.

Тон экрана — `Background tone` (0…1): красноватый, когда сломано (0,6–1,0), нейтральный, когда решение (0–0,15). Внутри блока меняй тон плавно `track`, на склейке можно резко.

## 3. Шрифты и кегли

- **JetBrains Mono** (`MONO`) — весь код и терминал. Ширина символа 0,6 em — по ней считаются колонки (`CW(fs)`, `cols()`).
- **Inter 800** (`TITLE`) — заголовок хука и субтитры. Меняется в `theme.ts`.
- Код: 40–44 px в карточках на всю ширину, 56 px — крупная одиночная команда, 32–36 px — терминал с несколькими строками, 28–30 px — стек ошибки, второстепенное.
- Заголовок хука: 88 px, 2 строки, по центру. При 3 широких словах в строке проверь ширину кадром.
- Субтитры: 50 px.
- Строка кода длиннее ~34 символов при 40 px не влезает в карточку 860 — сократи или уменьши кегль.

## 4. Раскладка

- Карточка: `Card` x=110, w=860, шапка 76 px; первая строка кода на `y + 104`, шаг строк 72–88 px.
- Две карточки друг под другом с зазором 30–60 px; общая высота контента ≤ 1130 px (полоса 230–1360).
- «Слева–справа» почти никогда не влезает — ставь вертикально.
- Заголовок хука на y ≈ 480–500, под ним главный объект (карточка на y ≈ 740–780).

## 5. Движение

### Камера
`Camera cam={{ fx, fy, s, kick, offsetX, blurX, glitch, seed }}` — точка мира `(fx, fy)` встаёт в центр полосы контента. Дорожки — `track(t, [[сек, значение], …])` (плавно, inOut).

**Камера по умолчанию стоит:**
- В блоке `s: 1` (или `s: smash` на смэш-кате), `fx: 540`, `fy` — постоянный центр контента блока. Раскладку блока строй так, чтобы всё влезало в полосу 230–1360 при `s = 1`.
- Никаких медленных наездов (`s` 1.0 → 1.03–1.07), дрейфа `fy`/`fx` на десятки пикселей и «следования» камеры за подсветкой.
- Пан допустим, только когда иначе новый контент не влезет, — один короткий пан (~0,6 с) в момент появления контента.
- Пустое место без событий дольше ~1 с заполняй движением **элементов**, а не камеры: каскад строк, подсветка `Band`, бегущая по строкам, счётчик, смена состояния элемента с толчком.
- Остаются: множитель смэш-ката (1.05 → 1 за ~0,3 с), толчки `shake`, хлыст — это склейки и удары, а не зумы.
- Сильный зум (1.2–1.3) — только как отдельный приём на маленький элемент; на карточке шириной 860 зум уводит края за отступы.
- `kick: shake(t, [[сек, сила], …])` — толчок на ударном слове. Сила 0,3–1,0, редко больше. Амплитуды уже маленькие — не увеличивай.

### Появления
- **По одному**: новый элемент — один за раз, с паузой ≥ 0,3–0,5 с. Если в фразе три важных слова — не обязательно три элемента; иногда достаточно рамки или смены цвета на уже видимом.
- `pop(t, a)` — пружина почти без перелёта (~0,35 с), основной способ появления. `ramp(t, a, b)` — для прозрачности, сдвигов, прорисовки линий.
- Группа (два одинаковых элемента, связка) появляется **целиком** одним событием.
- Вспышки `Flash` — слабые (0,12–0,3) и только на склейках/Enter.
- Убирай дубли смысла (несколько подписей про одно и то же).

### Изменение кода
1. Строку выделить (`Band`), остальное приглушить (обёртка с `opacity`) — камера не едет.
2. То, что меняется, — в красную рамку `Box`.
3. Само преобразование: стирание/печать `typing`, сдвиг символов.
4. Результат — в зелёную рамку.
Для акцента — рамка, а не масштаб.

### Склейки (2–4 на ролик, на смене смысла)
- **Смэш-кат**: новый блок начинается с `smash = interpolate(pop(t, START), [0,1], [1.06, 1])` в масштабе камеры + `Flash` 0,3. Множитель другого смэша внутри блока — только после его момента, иначе зум «прыгнет» заранее.
- **Хлыст**: конец блока `offsetX` 0 → ∓1400 и `blurX` 0 → 90 (Easing.in cubic, ~0,15 с), начало следующего — обратно (Easing.out, ~0,2 с).
- **Пролёт насквозь**: зум ×6–7 (Easing.in) в слово, затем смэш.

### Петля
Последний кадр = первый: та же раскладка, камера `(540, 795, 1)`, тон, никаких толчков на нулевой секунде (первый `kick` — с 0,04). Удобнее всего, когда последний блок показывает объект первого кадра при той же неподвижной камере. Первый кадр — понятная картинка без кода (уведомление, результат, файл), заголовка на нём нет; заголовок въезжает почти сразу — слова на 0,1 и 0,3 с, по 0,12 с на въезд (`words={[0.1, 0.3].map((a) => ramp(t, a, a + 0.12))}`). В конце этот объект «прилетает» на последней фразе, которая обрывается и переходит в первую.

### Залипательный хук
Первые ~2–2,5 с (первая фраза озвучки, въезд заголовка) — гипнотическая анимация, от которой трудно оторваться. **Концепцию согласуй с пользователем до кода**: 3–4 варианта с рекомендацией, затем выбор.

Что делает анимацию залипательной:
- **непрерывное движение с ритмом** — волна, спираль, цепочка ходов, маятники; не «появилось и стоит»;
- **самоподобие и повтор** — туннель, рекурсия, интерференция волн, гармоники (маятниковая волна: у каждого элемента своя частота, фазы то расходятся в змейку, то сходятся);
- **ускорение в середине, плавный финал** (`inOut`), в конце — схождение в главный объект ролика (кнопка, файл, строка) и акцент на нём (рамка);
- **связь с темой**: анимация показывает механику предмета, а не абстрактный узор.

Ограничения:
- кадр 0 — цельный понятный объект без анимации (петля); анимация начинается с ~0,1 с и к склейке возвращается к тому же объекту;
- камера стоит: зум, поворот и «ныряние» делаются **внутри элемента**, а не камерой;
- длительность — в пределах первой фразы озвучки; больше времени — только продолжая под следующей фразой, озвучку не растягивать паузами;
- один тихий звук на каждую фазу движения (`swoosh-short` / `swoosh-long`), акцент в конце — `tick` + `bass`.
- Мало: «плитки перевернулись два раза» — нужно непрерывное, затягивающее движение.

## 6. Таймлайн

Одна фраза — одна сцена; фразу длиннее ~4 с дели. Темп озвучки ~2,7 слова/с, длинные термины +0,5 с. Каждая сцена: таймкод, фраза дословно, «Начало / Движение (удары с таймкодами и словами) / Конец». Внутри блока конец сцены = начало следующей. Одна мысль на кадр: 2–3 строки кода, минимум текста. Смысл показывается через то, что разработчик реально видит: код, терминал, ошибки, CI, DevTools, — а не через картинки-метафоры. Без логотипов, персонажей, призывов к действию. Иллюстрации (то, чего нет в реальном инструменте) отмечай.

## 7. Каталог компонентов

### `anim.ts`
| | |
|---|---|
| `useBlockTime(START)` | время блока в секундах таймлайна (через карту озвучки) |
| `pop(t, a, damping=18)` | мягкое появление 0→1 |
| `ramp(t, a, b, easing?)` | 0→1 на отрезке (по умолчанию outExpo) |
| `fadeOut(t, a, d=0.2)` | 1→0 |
| `track(t, keys)` | дорожка камеры/тона |
| `typing(t, keys)` | число напечатанных символов, keys `[[сек, символов], …]` |
| `shake(t, kicks)` | толчки камеры |
| `blink(t)` | мигание курсора |
| `blockFrom(сек)`, `toNew`, `toOld` | карта времени (см. voice-and-captions.md) |

### `ui.tsx` (координаты — в мире, до камеры)
| Компонент | Что |
|---|---|
| `Background tone` | фон с красноватым тоном |
| `Camera cam id` | камера (см. выше) |
| `Flash o color` | вспышка экрана |
| `Card x y w h file dot fileColor` | карточка с шапкой-названием (файл, «terminal», «console») |
| `Code x y segs chars fs caret t opacity` | строка кода с печатью и курсором; `segs` — `{t, c}[]` (`lines.ts`: `cmd()`, `out()`) |
| `cols(x, y, c0, c1, fs)` | прямоугольник вокруг колонок c0..c1 строки — для `Box`, `Strike` |
| `Box r color p dashed` | рамка-выделение |
| `Strike r p color` | зачёркивание |
| `Squiggle x y w p` | волнистое подчёркивание ошибки |
| `Band x y w h color p` | подсветка строки |
| `Headline y lines words colors fs` | заголовок хука по словам |

Нужен новый элемент (чип, бейдж, статус-иконка, пайплайн CI, пуш-уведомление, дерево файлов, подсказка редактора) — добавь компонент в `ui.tsx` в том же стиле: абсолютные координаты мира через `abs(x, y)`, прогресс появления `p` (0…1, при `p ≤ 0.01` — `null`), цвета из `C`, шрифт `MONO`, скругления 10–26 px.

## 8. Подводные камни

- CSS-анимации и transition в Remotion не работают — всё от `t`.
- `pop(t, a)` до момента `a` = 0 → `interpolate(0, [0,1], [1.2, 1])` = 1.2: множители смэша считать только после склейки.
- Масштабирование соседних слов в строке съедает пробел — в заголовке слова «падают», а не растут; в субтитрах пробелы через `columnGap`.
- Слово, падающее сверху на вторую строку, налезает на первую — вторая строка поднимается снизу (уже так в `Headline`).
- Обёртка `position:absolute` без размеров уводит вложенные абсолютные элементы — задавай width/height.
- Braille-спиннер npm (`⠋⠙…`) — есть в JetBrains Mono.
